# 邮箱通知

在插件的通知设置中找到「邮箱通知」分组，选择发送方式，再配置发件邮箱、收件邮箱并点击「邮箱通知测试」。邮箱通知默认关闭，发送方式默认为「桌面端 SMTP」，与 Webhook 和系统通知分别控制。

## 桌面端 SMTP（默认）

填写 SMTP 服务器、端口、连接加密方式和密码或授权码。用户名通常为完整邮箱地址；留空时使用发件邮箱。QQ、163 等邮箱通常需要先在邮箱设置中开启 SMTP，并使用邮箱生成的授权码。

SSL/TLS 连接通常使用 465 端口，STARTTLS 通常使用 587 端口，具体以邮箱服务的配置为准。SMTP 发信需要思源桌面端保持打开，浏览器和手机端不能直接连接 SMTP。

SMTP 邮件由桌面端执行，内核负责生成提醒、保存待发送记录和安排重试。多个窗口通过独立的邮件领取记录避免同时发送，与内部弹窗、系统通知的显示状态无关。

## 邮件 API（Docker 用户）

Docker 或浏览器用户可将「发送方式」切换到「邮件 API」。API 邮件由思源内核后台发送，无需打开桌面页面，但思源服务必须保持运行。

「邮件服务」默认选择「自定义（兼容 Resend API）」，填写邮件 API 地址及 API 密钥。也可选择 SMTP2GO 或 Resend 预设，在对应服务创建 API 密钥并验证发件人，随后填写发件邮箱和收件邮箱。已有 API 邮件配置会继续使用 API 方式。

- [SMTP2GO 配置说明](https://developers.smtp2go.com/docs/send-an-email)
- [Resend 发信接口说明](https://resend.com/docs/api-reference/emails/send-email)

测试按钮使用当前表单配置，即使尚未启用自动通知也可以测试。测试成功表示邮件服务器已接受邮件，实际投递结果以收件箱和邮件服务的发送记录为准。

## 自动通知

打开「启用邮箱通知」后，任务到期提醒、习惯提醒和每日任务汇总会通过邮件发送。每日汇总沿用「每日任务提醒」的开关和发送时间，需要同时开启该功能；汇总正文包含全部任务。

邮箱通道使用独立的发送记录，失败后每隔 30 秒重试，最长重试 5 分钟；任务已完成或习惯已打卡时取消重试。邮箱与 Webhook 可以同时启用，一个通道失败不会导致另一个通道重复通知。

## 自定义邮件服务

选择「自定义（兼容 Resend API）」后，填写「邮件 API 地址」。该地址需接受以下请求，使用 `Authorization: Bearer <API 密钥>` 认证：

```json
{
    "from": "sender@example.com",
    "to": ["recipient@example.com"],
    "subject": "任务提醒",
    "text": "完整通知正文"
}
```

成功响应需为 HTTP 2xx，并返回含非空字符串 `id` 的 JSON，例如 `{"id":"email-123"}`。自动通知包含稳定的 `Idempotency-Key` 请求头；服务可用它防止重试造成重复发信。
