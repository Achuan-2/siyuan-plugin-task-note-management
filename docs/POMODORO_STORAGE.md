# 番茄钟统计与存储

原始数据仍保存在 `pomodoroRecords/YYYY-MM-DD.json`。统计摘要是可重建缓存，不能用于替代或覆盖尚未加载的会话明细。

## 读取与更新

- 启动读取本机摘要和日期目录，根据修改时间检查差异。缓存有效且源文件稳定时，不读取历史明细。
- 缺少摘要、摘要版本不兼容、某天摘要损坏时，重建对应范围。明细读取最多 6 个并发，首次重建完成后释放历史明细，仅保留摘要和会话 ID 到日期的索引。
- 任务累计、今日统计、习惯关联、任务总结、趋势、热力图和分类饼图使用摘要。日历时间线、记录列表和历史记录编辑按日期范围或关联任务加载明细。
- 内核通知提供具体日期时，前端在 100 ms 内合并日期，只刷新相关文件并发出一次界面更新。没有具体路径的数据同步通知执行目录差异检查。
- 保存先更新原始日期文件，全部成功后替换相关日期的统计贡献并持久化摘要。前端与内核分别串行处理本实例的编辑和刷新，避免未落盘编辑被刷新覆盖。

## 缓存位置与校验

前端和内核分别使用工作空间下的 `temp/petal/<插件名>/pomodoro-stats/frontend.json`、`kernel.json`，通过文件 API 读写。这些文件不参与数据同步，不广播业务变更。清除临时目录后会自动重建；缓存读写失败不影响原始数据保存。

缓存校验包括格式版本、摘要结构、目录新增/删除和文件修改时间。目录接口的修改时间只有秒精度，验证时间距文件修改不足两秒的摘要会保守重读，覆盖同秒连续编辑。明确的日期变更通知始终读取指定源文件，不依赖时间戳。

`refreshData(true)` 和 `loadPomodoroRecords(true)` 提供完整重读。通过外部工具恢复历史文件并刻意保留原修改时间时，应执行完整重读或清除统计缓存；目录元数据无法识别内容与时间戳均被恢复的情况。

## 写入与兼容

补录、时长修改、备注修改、计时开始/结束及 MCP 写入统一经过记录管理器，先加载受影响日期的明细，避免用摘要占位记录覆盖历史会话。跨天移动先写目标日，后续写入失败时尝试恢复已写日期；恢复本身失败会明确报错，不宣称跨文件原子事务。

修改一天起始时间会加载全部明细，再按逻辑日期重新分组。旧版单文件 `pomodoro_record.json` 可以回退读取，首次写入时迁移完整历史。原有正计时数量、旧记录 `count` 规则、重复实例、休息和进行中记录的统计边界保留；文档内标记的逐条取整与日历的会话时长口径分别保存在摘要中。

## 验证

`node --test scripts/test-pomodoro-storage.cjs` 使用隔离的内存文件适配器验证请求数、并发上限、缓存恢复、按需读取、统计口径、跨天移动、保存失败恢复和视图加载边界。其中 1000 日数据用于检查冷启动读取 1000 个文件、缓存有效的再次启动读取 0 个明细文件；这些是受控请求数，并非真实思源加载耗时或内存测量。
