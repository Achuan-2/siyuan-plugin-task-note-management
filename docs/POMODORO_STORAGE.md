# 番茄钟统计与存储

原始数据保存在 `pomodoroRecords/YYYY-MM-DD.json`，本机统计缓存按月保存。原始会话是事实来源；统计摘要可以删除重建，不能用于覆盖尚未加载的明细。

## 物理日期与逻辑日期

新会话按开始时的本地自然日选择文件。会话保存 `storageDate` 和 `timezoneOffsetMinutes`，时间统一写为 ISO 绝对时间；之后编辑开始时间仍在原文件更新，避免跨文件搬移。记录的 `duration` 是实际专注时长，不能用起止时间差替代，暂停时间不计入专注。

统计使用逻辑日：将会话开始时的当地时间减去“一天起始时间”后取日期。例如起始时间为 03:00，11 月 4 日 01:00 的新记录写入 `2026-11-04.json`，统计归入 11 月 3 日。同一物理文件可以贡献两个逻辑日，一个逻辑日也可以从多个物理文件汇总；日期范围查询先通过索引定位这些文件，再筛选会话。

修改一天起始时间只读取明细并重建索引，不写入、重命名或删除原始文件。全部读取成功后才发布新索引，失败时保留旧索引。旧版按逻辑日命名的文件继续在原位置读写，不自动迁移；旧记录没有时区偏移时按当前设备时区解释，编辑时补全元数据。仅有每日累计值而没有对应明细的历史余额保留原日期。

## 读取与更新

- 启动读取本机摘要和日期目录，根据修改时间检查差异。缓存有效且源文件稳定时，不读取历史明细。
- 缺少摘要、摘要版本不兼容、某天摘要损坏时，重建对应范围。明细读取最多 6 个并发，首次重建完成后释放历史明细，仅保留摘要和会话 ID 到日期的索引。
- 任务累计、今日统计、习惯关联、任务总结、趋势、热力图和分类饼图使用摘要。日历时间线、记录列表和历史记录编辑按日期范围或关联任务加载明细。
- 内核通知提供具体日期时，前端在 100 ms 内合并日期，只刷新相关文件并发出一次界面更新。没有具体路径的数据同步通知执行目录差异检查。
- 保存先更新原始日期文件，全部成功后替换相关日期的统计贡献。摘要按月标记为待写，合并 500 ms 内的变化并在后台保存；记录保存与界面反馈不等待缓存落盘。
- 明细按最近使用情况保留 62 个物理日期分片，淘汰时同时释放恢复副本。大范围读取或绘图期间暂时保留所需明细，生成结果后释放；统计摘要与会话定位索引保留。

## 缓存位置与校验

前端和内核分别使用工作空间下的 `temp/petal/<插件名>/pomodoro-stats/frontend/`、`kernel/`。每个目录包含 `manifest.json` 和 `YYYY-MM.json` 月摘要；编辑单日只重写对应月份，月份列表变化时才重写清单。这些文件不参与数据同步，不广播业务变更。旧版单文件摘要会忽略并自动重建；缓存读写失败不影响原始数据保存，卸载时清理定时器并尽力提交待写摘要。

缓存校验包括格式版本、一天起始时间、设备时区偏移、摘要结构、目录新增/删除和文件修改时间。配置变化会重建索引；已保存时区偏移的新记录仍按记录时的当地日期归属。目录接口的修改时间只有秒精度，验证时间距文件修改不足两秒的摘要会保守重读，覆盖同秒连续编辑。明确的日期变更通知始终读取指定物理文件，不依赖时间戳。

`refreshData(true)` 和 `loadPomodoroRecords(true)` 提供完整重读。通过外部工具恢复历史文件并刻意保留原修改时间时，应执行完整重读或清除统计缓存；目录元数据无法识别内容与时间戳均被恢复的情况。

## 写入与兼容

补录、时长修改、备注修改、计时开始/结束及 MCP 写入统一经过记录管理器，先加载受影响物理日期的明细。前端通过 `commit-pomodoro-records` RPC 和 MCP 共用内核写入队列，读取最新记录后按会话 ID 合并：不同会话的并发增改可以合并，同一会话被修改时明确报冲突，拒绝用陈旧快照覆盖。没有内核插件的旧宿主使用同源 Web Locks；内核 RPC 暂时不可用时不绕过协调器写入。

记录写入使用 `schemaVersion: 2`。会话新增和修改由协调器生成递增的 `revision` 与 `updatedAt`；内容改回原值时版本仍递增，旧编辑窗口无法绕过冲突检查。相同请求重放不重复累计。删除后在原文件的 `tombstones` 中保留 ID、版本和时间，索引保留删除位置；陈旧快照、重启后的请求及向其他分片补录相同 ID 均拒绝恢复。删除标记暂不自动清理，不能删除整个空文件来替代删除会话。

保存失败时尝试恢复所有已尝试的日期，包括请求失败但实际已落盘的情况。恢复时发现文件又被外部修改则停止覆盖并报错；该实例在重新读取源记录前拒绝后续写入。协调队列保证同一内核内插件写入的互斥，版本和删除标记保护经过协调器的提交；跨设备同步直接覆盖整份文件、外部编辑和进程崩溃仍不属于原子事务保证，也没有自动合并同步冲突文件。

旧版单文件 `pomodoro_record.json` 可以回退读取，首次写入时迁移完整历史。原有正计时数量、旧记录 `count` 规则、重复实例、休息和进行中记录的统计边界保留；文档内标记的逐条取整与日历的会话时长口径分别保存在摘要中。后台习惯提醒同样使用逻辑日摘要，包含直接专注及关联任务的已结束会话。

## 验证

`node --test scripts/test-pomodoro-storage.cjs` 使用隔离的内存文件适配器验证请求数、并发上限、缓存恢复、按需读取、统计口径、双实例冲突、日界限重建不写源文件、分钟边界、时区偏移、旧文件与新文件的贡献合并、版本和持久删除标记。1000 日数据检查冷启动读取 1000 个文件、有效缓存再次启动读取 0 个明细文件；150 日浏览检查明细及恢复副本限制为 62 个分片。修改一个月中的记录只更新该月缓存，不重写全量历史摘要。

`test/test-kernel-webhook.cjs` 检查习惯提醒按逻辑日摘要计算达标；`test/test-kernel-bundle.cjs` 在无 DOM 的构建产物中验证真实内核接线、前端 RPC 与 MCP 并发写入，以及从次日自然日文件读取凌晨专注。这些验证不等同于真实思源加载耗时、堆内存或跨设备同步验收。
