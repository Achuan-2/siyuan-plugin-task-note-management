# 番茄钟统计与存储

原始数据仍保存在 `pomodoroRecords/YYYY-MM-DD.json`。统计摘要是可重建缓存，不能用于替代或覆盖尚未加载的会话明细。

## 读取与更新

- 启动读取本机摘要和日期目录，根据修改时间检查差异。缓存有效且源文件稳定时，不读取历史明细。
- 缺少摘要、摘要版本不兼容、某天摘要损坏时，重建对应范围。明细读取最多 6 个并发，首次重建完成后释放历史明细，仅保留摘要和会话 ID 到日期的索引。
- 任务累计、今日统计、习惯关联、任务总结、趋势、热力图和分类饼图使用摘要。日历时间线、记录列表和历史记录编辑按日期范围或关联任务加载明细。
- 内核通知提供具体日期时，前端在 100 ms 内合并日期，只刷新相关文件并发出一次界面更新。没有具体路径的数据同步通知执行目录差异检查。
- 保存先更新原始日期文件，全部成功后替换相关日期的统计贡献。摘要按月标记为待写，合并 500 ms 内的变化并在后台保存；记录保存与界面反馈不等待缓存落盘。
- 明细按最近使用情况保留 62 天，淘汰时同时释放恢复副本。大范围读取、重新分组或绘图期间暂时保留所需明细，生成结果后释放；统计摘要与会话定位索引保留。

## 缓存位置与校验

前端和内核分别使用工作空间下的 `temp/petal/<插件名>/pomodoro-stats/frontend/`、`kernel/`。每个目录包含 `manifest.json` 和 `YYYY-MM.json` 月摘要；编辑单日只重写对应月份，月份列表变化时才重写清单。这些文件不参与数据同步，不广播业务变更。旧版单文件摘要会忽略并自动重建；缓存读写失败不影响原始数据保存，卸载时清理定时器并尽力提交待写摘要。

缓存校验包括格式版本、摘要结构、目录新增/删除和文件修改时间。目录接口的修改时间只有秒精度，验证时间距文件修改不足两秒的摘要会保守重读，覆盖同秒连续编辑。明确的日期变更通知始终读取指定源文件，不依赖时间戳。

`refreshData(true)` 和 `loadPomodoroRecords(true)` 提供完整重读。通过外部工具恢复历史文件并刻意保留原修改时间时，应执行完整重读或清除统计缓存；目录元数据无法识别内容与时间戳均被恢复的情况。

## 写入与兼容

补录、时长修改、备注修改、计时开始/结束及 MCP 写入统一经过记录管理器，先加载受影响日期的明细。前端通过 `commit-pomodoro-records` RPC 和 MCP 共用内核写入队列，读取最新记录后按会话 ID 合并：不同会话的并发增改可以合并，同一会话被修改或移动时明确报冲突，拒绝用陈旧快照覆盖。没有内核插件的旧宿主使用同源 Web Locks；内核 RPC 暂时不可用时不绕过协调器写入。

跨天移动先写目标日，后续写入失败时尝试恢复所有已尝试的日期，包括请求失败但实际已落盘的情况。恢复时发现文件又被外部修改则停止覆盖并报错；该实例在重新读取源记录前拒绝后续写入。协调队列保证同一内核内插件写入的互斥；跨设备同步、外部文件编辑和进程崩溃不属于跨文件原子事务保证。

修改一天起始时间会加载全部明细，在独立对象中计算新分组；提交时校验完整日期列表和每个源记录，成功后才替换内存状态。失败后旧内存及统计仍可用于后续记录，不会因预先清空内存而覆盖历史。旧版单文件 `pomodoro_record.json` 可以回退读取，首次写入时迁移完整历史。原有正计时数量、旧记录 `count` 规则、重复实例、休息和进行中记录的统计边界保留；文档内标记的逐条取整与日历的会话时长口径分别保存在摘要中。

## 验证

`node --test scripts/test-pomodoro-storage.cjs` 使用隔离的内存文件适配器验证请求数、并发上限、缓存恢复、按需读取、统计口径、双实例增改冲突、跨天移动、重新分组失败后继续写入、缓存写入挂起和明细淘汰。1000 日数据检查冷启动读取 1000 个文件、有效缓存再次启动读取 0 个明细文件；150 日浏览检查明细及恢复副本限制为 62 天。`test/test-kernel-bundle.cjs` 在无 DOM 的构建产物中验证前端 RPC 与 MCP 并发写入共用队列。这些验证不等同于真实思源加载耗时、堆内存或跨设备同步验收。

1000 日、每天一条会话的合成数据中，完整摘要 JSON 为 415,022 字节；修改 2021-06-15 的备注后，月份摘要仅包含 30 日、12,463 字节，约为完整摘要的 3%。原始日期文件写入一次；若明细尚未加载，需要一次明细读取及一次协调器提交前的最新记录读取。这里比较的是 JSON 载荷大小与请求数，不是实际耗时加速比例。
